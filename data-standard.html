Goals

Why this standard exists

Business data should outlive the app that created it. These four principles shape every kind, tag, and payload convention on this page.

01

Own your data

Let stores own and move business data without a platform lock-in.

02

Replay and audit

Make POS, ERP, CRM, inventory, supplier, and marketplace events replayable and auditable.

03

Privacy by default

Keep public discovery data open while sensitive data can be encrypted with NIP-44-compatible payloads.

04

Integrate anything

Give apps, relays, indexers, AI agents, and partner systems a stable kind registry to integrate against.

Event rules

Rules every implementation follows

Keep events portable, tenant-aware, and safe to publish. If a rule cannot be met, treat the event as private and keep it out of the public registry.

Rule 01

Replaceable business records

Kinds in the 30000-39999 range should include a stable d tag. Use the d value as the local business identifier.

Rule 02

Tenant context

Events that belong to a company or branch should include company and branch tags when public metadata is safe to expose.

Rule 03

Private fields

Customer PII, staff secrets, cost data, and internal notes should be encrypted in content or omitted from public events.

Rule 04

Versioning

Breaking schema changes require a new minor draft version and a migration note in this standard.

Contributing

Updating the registry

This page is generated. Edit docs/public-standard/standard.json and regenerate — changes made directly to this HTML will be overwritten on the next build.

  1. 01

    Add or change the implementation kind constant.

  2. 02

    Update docs/public-standard/standard.json with range, description, status, and migration notes.

  3. 03

    Run npm run docs:standard.

  4. 04

    Review docs/public-standard/kinds.md and public/data-standard.html.

  5. 05

    Commit code and generated docs together.

  6. 06

    Run npm run docs:publish when sites/bitos.space is available, then push the website repo.
