Goals

01

Let stores own and move business data without a platform lock-in.

02

Make POS, ERP, CRM, inventory, supplier, and marketplace events replayable and auditable.

03

Keep public discovery data open while sensitive data can be encrypted with NIP-44-compatible payloads.

04

Give apps, relays, indexers, AI agents, and partner systems a stable kind registry to integrate against.

Event Rules

Replaceable business records

Kinds in the 30000-39999 range should include a stable d tag. Use the d value as the local business identifier.

Tenant context

Events that belong to a company or branch should include company and branch tags when public metadata is safe to expose.

Private fields

Customer PII, staff secrets, cost data, and internal notes should be encrypted in content or omitted from public events.

Versioning

Breaking schema changes require a new minor draft version and a migration note in this standard.

Tag Conventions

Tag Meaning
d Stable record identifier for parameterized replaceable events.
company Company identifier, usually a public event id or stable slug.
branch Branch identifier for branch-scoped operations.
p Related user, staff, supplier, customer, agent, or app public key.
e Related event such as an order, payment, invoice, audit log, or source document.
status Workflow status for records that need relay/indexer filtering.
scope Visibility or permission scope such as public, company, branch, staff, or encrypted.

Updating the Registry

When a new kind, field, or feature is added, update the standard definition inside docs/public-standard/standard.json and regenerate this public document page before committing.

  1. Add or change the implementation kind constant.
  2. Update docs/public-standard/standard.json with range, description, status, and migration notes.
  3. Run npm run docs:standard.
  4. Review docs/public-standard/kinds.md and public/data-standard.html.
  5. Commit code and generated docs together.
  6. Run npm run docs:publish when sites/bitos.space is available, then push the website repo.
